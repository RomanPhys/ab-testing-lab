# A/B Testing Lab: CUPED, дельта-метод, бутстрэп и проверка методов на A/A-тестах

Небольшая платформа для анализа экспериментов на маркетплейсе. Пользователи симулируются, их события
пишутся в SQL-хранилище, из него SQL собирает витрину метрик, а по витрине считаются статистические
тесты. Сами методы я проверил Монте-Карло на данных, где истинный эффект известен заранее.

Monte Carlo, 1000 A/A и 1000 A/B экспериментов по 40 000 пользователей (`results/validation.md`).

## Интуиция и формулы

### CUPED

По сути это метод контрольных переменных из Монте-Карло. Выручка пользователя складывается из сигнала
(эффекта эксперимента) и большого фона, а фон можно оценить заранее по предпериоду. Его и вычитаем:

`y' = y - θ(x - E x)`, где `θ = Cov(y, x) / Var(x)`.

Так как `x` измерен до рандомизации, оценка остаётся несмещённой, а `Var(y') = Var(y)(1 - ρ²)`.
Если ковариат несколько, это проекция `y` на их линейную оболочку, и дисперсия падает на долю `R²`.

### Дельта-метод

Это та же формула распространения ошибок, что в физпраке. Для `R = mean(N) / mean(D)` линеаризация
первого порядка даёт

`Var R ≈ (Var N - 2R·Cov(N, D) + R²·Var D) / (n·μ_D²)`.

Важно, что считается единицей рандомизации. Мы рандомизируем пользователей, поэтому независимы пары
`(N_u, D_u)` по пользователям. Отдельные сессии независимыми считать нельзя.

### Почему наивный тест врёт

У сессий одного пользователя общая склонность к покупке `p_u`, и они положительно скоррелированы.
Наивный тест считает их независимыми и завышает эффективный размер выборки. Доверительный интервал
выходит слишком узким, ложных срабатываний становится больше. В физике это та же ошибка, что принять
автокоррелированные измерения за независимые.

## Что внутри

```
notebooks/ab_experiment_analysis.ipynb   весь разбор с сохранёнными выводами (SQL, SRM, MDE,
                          эффекты, сегменты, A/A-проверка, витрины, дашборд)
sql/user_metrics.sql      CTE + LEFT JOIN + CASE, метрики на пользователя (эксперимент и предпериод)
sql/mart_daily.sql        аддитивная витрина для BI (день x вариант x платформа), оконная функция
sql/srm.sql               проверка Sample Ratio Mismatch
sql/daily_gmv.sql         оконные функции, кумулятивная выручка по дням
src/ablab/population.py   генеративная модель (Gamma-активность, Beta-конверсия, LogNormal-чек),
                          hash-сплит пользователей как на реальных платформах
src/ablab/db.py           событийное SQLite-хранилище (users, assignments, sessions, orders)
src/ablab/stats.py        Welch, CUPED, regression adjustment, дельта-метод, Poisson bootstrap,
                          Mann-Whitney, SRM, MDE и размер выборки
scripts/run_case_study.py один эксперимент целиком: MDE, SRM, метрики, CUPED, сегменты с поправкой Холма
scripts/run_validation.py Monte Carlo, калибровка FPR и мощность всех методов
docs/datalens.md          как собрать дашборд в Yandex DataLens поверх витрин
tests/                    дельта-метод против бутстрэпа, несмещённость CUPED, SRM, обратимость MDE
```
